# 网络、跨网与账号准备

## 先记录网络/执行侧矩阵

不要只问“能否上网”。按选定模式把每项填入下表，列状态 `ready / pending / unknown`；仅经同意做必要的只读连接/身份检查，不打印秘密、环境全量或原始认证日志。

| 服务/资源 | A 默认同侧在哪侧访问 | B Windows＋WSL 哪侧访问 | 用户需准备 |
| --- | --- | --- | --- |
| DSH/模型 API | 已确认的 Host/profile 所在环境 | Windows Host | 已批准 provider/model、费用、网络和允许发送的数据类别 |
| GitHub API / Git remote | 同侧原生执行环境 | 选定 distro/user 的原生 gh/Git | 端点、Agent 账号邀请/写权限、专用 wrapper、获准网络 |
| 业务 clone、依赖/构建 | 同侧原生执行环境 | 选定 WSL 用户/工作目录 | 基础 clone、包镜像、证书、编译依赖及许可证 |
| 插件源码与依赖下载 | 已选代码来源的 checkout 环境 | WSL 源码构建侧 | 可达的官方/fork 来源、锁定 revision/lockfile、批准的 registry |
| 管理 UI | 已确认的 URL/profile | 现有 Windows Desktop URL/profile | 本机访问、既有身份授权，不自动改外网监听/防火墙 |
| 额外来源 | 仅所选代码版本支持且用户选择时 | 本轮 GitHub-only | 默认工作方式不代表飞书等功能已适配；单独核实兼容性 |

B 中 Windows 浏览器能访问 API，不证明 WSL 中的专用 CLI 可访问；WSL 能访问，也不证明 Host 模型 API 可访问。不要导出完整环境找密码，或用另一个 OS 用户/Windows `.exe` 偷换执行身份。

## 由用户选择准备路线

### 无跨网

各侧可直接访问获准服务。核对域名/仓库/模型服务与网络范围，按清单准备；无需安装 VPN、第二主机或网络桥。仍需明确允许哪些代码/日志进入模型与 GitHub。

### 同机受控代理/VPN/证书

先让用户在正确侧准备获准连接、系统/工具信任的 CA、包镜像及必要代理。记录其范围、由谁维护和如何撤回，不接收密码/Token。需要改变服务级环境、系统 PATH、CA store 或安装依赖时单独列计划获批；不修改无关 profile/Windows 全局环境，不使用 `--insecure`、禁用 SSL/签名或随机公共代理。登录页面/终端留给用户完成，不启动个人浏览器配置搜 cookie。

### 隔离网/双机/人工中转

先确认：哪台运行 DSH/模型、哪台执行 Git/构建，是否允许代码/patch/日志离开内网，获准的传输介质/通道，谁核对 commit SHA/哈希、脱敏与回滚，凭据如何留在各自信任域。数据路径和身份路径分别审查。

本技能/适配插件**不自动实现**跨机调度、SSH backend、账号同步或“内网 GitCode 当 GitHub API”替换。没有批准且可验证的连接/人工交接方案就停在准备阶段，不谎称一台 Host＋WSL 的本地映射已经解决跨网。若要改为官方独立部署，需要用户重新确认工作方式，不自动新开 Linux DSH/第二服务。

## GitHub 账号与数据责任

1. 确认 `github.com` 目标 `owner/name` 和 Agent 专用**用户账号**；不是 GitHub App，不复用操作者个人登录。用户创建账号、接受邀请并授予必要仓库权限。
2. 在实际执行侧建立专用 GH_CONFIG_DIR/wrapper，与个人配置分开。用户在自己的终端执行 wrapper 的 `auth login`；不要在聊天贴 Token、密码、二次验证码或凭据文件，不修改个人 `gh auth` 默认账号来省事。
3. 经批准只读核验 wrapper 的 `api user` 与目标 repo 的稳定 ID/权限；只报告必要身份/状态，隐藏认证错误里的敏感输出。不自动 `push`、发评论、创建 PR 或触发通知测试。
4. GitHub 权限不等于允许把内网源码公开或发送给外部模型。确认仓库可见性、允许同步的内容、模型数据边界和操作责任；不复制其他环境的凭据作为中转。
5. 不对 GitHub Enterprise/GitCode 作兼容承诺。要求这些端点时先查所选版本支持边界；不以改 hostname 绕过接口语义，不更换目标 repo ID 掩盖历史状态。

准备完成后重新检查各侧的真实身份、网络与工具。用户说“已准备好”是重新验证的起点，不等于允许真实模型/业务写操作；模型测试、业务试运行、恢复来源/processing 和任何调度均分别明确确认。
